**Scope:** Dev Migration Assistant 1.0 — the macOS Electron app, the `.devbackup` container, and the restore path.
**Status:** living document. Every row names the code that implements the mitigation and the test that
demonstrates it. Every row's **Validated by** cell names a passing test at the tagged release commit; the
1.0.0 security gate (§5) was walked on 2026-08-28.

## 1. Assets

| Asset                                                                          | Why it matters                                                                                   |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| Source code, uncommitted changes, untracked files                              | Unpublished work; may be proprietary.                                                            |
| Claude Code transcripts, memory, history, checkpoints                          | Contain prompts, tool output and file contents; may echo secrets (tokens pasted, `.env` cat'ed). |
| Env files, MCP `env`/`headers` blocks, local settings                          | Frequently hold API keys and tokens.                                                             |
| Credentials (Keychain items, `oauthAccount` in `~/.claude.json`, session keys) | Grant access to accounts. **Never migrated.**                                                    |
| The backup password                                                            | The only secret protecting a `.devbackup` at rest.                                               |
| Integrity of the user's existing data on both machines                         | Backup must never mutate the source; restore must never write outside what the user approved.    |
| The user's machine (code execution, filesystem)                                | A malicious backup or project must not be able to run code or write arbitrary files.             |

## 2. Trust boundaries

```text
 untrusted ───────────────────────────────────────────────────────────────────────── trusted
  ┌──────────────┐  typed IPC   ┌──────────────┐   Exec(args[])   ┌──────────────┐
  │  Renderer    │ ───────────▶ │  Main        │ ───────────────▶ │ git / open   │
  │  (sandboxed) │ ◀─────────── │  (privileged)│                  └──────────────┘
  └──────────────┘  envelopes   │  + Core      │   ScopedFs       ┌──────────────┐
                                │              │ ───────────────▶ │ approved     │
  ┌──────────────┐  zod +       │              │                  │ destinations │
  │ .devbackup   │ ───────────▶ │  Archive     │                  └──────────────┘
  │ (untrusted)  │  hardened    └──────────────┘
  └──────────────┘  extraction         ▲ read-only
  ┌──────────────┐                     │
  │ project      │ ────────────────────┘  file names, branch names, remotes are DATA
  │ content      │
  └──────────────┘
```

1. **Renderer → Main.** The renderer is untrusted (ADR-0007): `sandbox: true`, `contextIsolation: true`,
   `nodeIntegration: false`, strict CSP, no `ipcRenderer` exposed. Every request crosses a whitelisted channel
   declared in `packages/ipc-contracts/src/channels.ts` with a zod request schema; main validates the sender frame and
   returns errors as values (`IpcEnvelope`), never throwing across the bridge.
2. **Backup file → Archive/Core.** On restore the `.devbackup` is hostile input: header bounds are checked before any
   crypto, the manifest is zod-validated before any other entry is accepted, tar entries are filtered by an entry
   guard, limits enforced, checksums verified, and extraction only ever targets a fresh private staging directory.
3. **Providers → filesystem.** Providers never receive raw `fs`. Backup gives them a `ScopedFs` rooted at their
   staging subdirectory; restore gives them a `ScopedFs` whose roots are exactly the destinations approved in the
   plan (`packages/shared/src/scoped-fs.ts`). Reads are unrestricted; every write checks the canonical target and the
   real path of its nearest existing ancestor.
4. **Project content → subprocesses.** File names, branch names, remote URLs and worktree paths found in a project
   are data. They reach `git` only as validated argv elements through `Exec` (`packages/shared/src/exec.ts`); there
   is no code path that builds a shell string.
5. **App → OS.** `dialog.showOpenDialog`, `shell.openExternal` (https only) and "open in Terminal" run in main on
   canonicalised paths; the renderer only ever receives selected paths.

## 3. Attacker models

| Id  | Attacker                                | Capabilities                                                                                                                           | Goal                                                                                |
| --- | --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| A1  | **Stolen `.devbackup`**                 | Has the file (lost SSD, shared drive, leaked cloud folder); unlimited offline compute; no password.                                    | Read code, transcripts, env files.                                                  |
| A2  | **Malicious / tampered backup**         | Delivers a crafted or modified `.devbackup` to the user (phishing, "here is my project", corrupted transfer).                          | Write files outside the chosen destination, execute code, crash or exhaust the app. |
| A3  | **Malicious project content**           | Controls a repository the user selects for backup or restores: file names, branch names, remote URLs, worktree paths, `.claude` files. | Inject arguments into `git`, escape staging, plant files elsewhere, run hooks.      |
| A4  | **Compromised renderer**                | Achieves JS execution in the renderer (XSS via rendered transcript text, dependency compromise).                                       | Reach Node, the filesystem, `git`, or unapproved destinations through IPC.          |
| A5  | **Local attacker with temp-dir access** | Another local user or process that can read/write `os.tmpdir()` while a job runs or after a crash.                                     | Read staged plaintext, swap staged files before they are written (TOCTOU).          |
| A6  | **Environmental failure**               | Cancellation mid-operation, crash, disk full, Claude Code running while restore writes to `~/.claude`.                                 | Leave the user with corrupted, half-written or lost data.                           |

Explicitly **out of scope**: an attacker who already runs as the user with the app's privileges (they can read
`~/.claude` directly), weak user-chosen passwords beyond the enforced minimum, and vulnerabilities in Claude Code,
Git or macOS themselves.
