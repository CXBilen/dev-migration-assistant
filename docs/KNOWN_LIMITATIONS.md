# Known limitations (1.0)

**Status: finalized for the 1.0.0 release.** Every row was confirmed against the shipped code before tagging; a row
added after a tag is marked _to be finalized_ until the next release confirms it. This list is derived from the
ADRs, the research notes and the provider implementations. Items marked _design_ are deliberate; items marked _gap_
are things we would like to do and have not done yet. Nothing here is hidden from the user: where the app cannot
capture or restore something, the scan summary, restore plan or final report says so.

Provider-level detail lives in [`docs/providers/`](providers/) (`git.md`, `claude-code.md`, `project-files.md`,
`runtime.md`).

| ------------------------------------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| macOS 13+ on Apple Silicon only; no Intel build, no universal build | gap    | `pnpm --filter @devmig/desktop dist:mac:universal` exists but is untested; a universal build is on the [roadmap](ROADMAP.md) for 1.2.                          |

| No command-line interface                                           | gap    | `@devmig/core` is headless and testable, but 1.0 ships no CLI binary.                                                                                          |
| English only                                                        | gap    |                                                                                                                                                                |

## The `.devbackup` container

| Limitation                                                       | Kind   | Notes                                                                                                                                                                                                                                                                                                  |
| ---------------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| No password recovery                                             | gap    | A forgotten password means an unreadable backup. A recovery key (second key wrap in the header, `formatVersion` 2) is planned for 1.2.                                                                                                                                                                 |
| No compression                                                   | gap    | Transcripts compress 5–10×; 1.0 stores the tar stream uncompressed inside the encryption and the reader refuses gzip payloads, so the extraction path has no decompression surface. Optional gzip inside the encryption is planned for 1.2 ([ADR-0003](architecture/adr/0003-devbackup-container.md)). |
| One file, whole payload                                          | design | No incremental or differential backups; every backup is complete. The file can be large (tens of GB for big monorepos); FAT32 media cannot hold files over 4 GiB.                                                                                                                                      |
| Hard size limits on restore                                      | design | Extraction refuses payloads over 200 GiB total, 2,000,000 entries, 50 GiB per entry, 1024-character paths or 128 directory levels (`DEFAULT_EXTRACTION_LIMITS`); `manifest.json` ≤ 64 MiB, `checksums.json` ≤ 256 MiB. The GCM construction itself has no size ceiling because the payload is chunked. |
| Header metadata is visible without the password                  | design | Format version, KDF parameters, chunk size, creation time, app version, an opaque backup id and the approximate size are readable by anyone holding the file. No labels, paths or names are in the header.                                                                                             |
| Argon2id default cost: 64 MiB of RAM, roughly 0.1–0.5 s per open | design | Writers use `m = 64 MiB, t = 3, p = 4` (RFC 9106 "second recommended" option). Readers accept parameters down to 8 MiB / 1 pass / 1 lane and cap them at 1 GiB / 16 passes / 16 lanes so a hostile header cannot demand more; the derivation blocks the calling thread for its duration.               |
| A corrupted backup is unrecoverable                              | design | Authenticated encryption fails closed on the first bad chunk; there is no error-correction data. Keep two copies of important backups.                                                                                                                                                                 |
| The output file must be on a local, writable folder              | design | The writer creates `<name>.devbackup.partial` next to the final file and renames on success; the destination folder must exist and be writable. An existing file at the output path is refused.                                                                                                        |

## Git provider

| Limitation                                                                               | Kind   | Notes                                                                                                                                                                                                                                                                                                 |
| ---------------------------------------------------------------------------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Submodules are not captured                                                              | gap    | The bundle covers the superproject only; run `git submodule update --init` on the destination. Submodule working-tree changes are not migrated. The scan warns (`! submodules not captured`).                                                                                                         |
| Stashes are not captured                                                                 | gap    | `git bundle --all` may carry `refs/stash`, but restore fetches only heads, tags and remote-tracking refs, so stash entries are not recreated. Apply or export stashes before backing up; the scan warns (`! N stashes not captured`) and `git stash list` is expected to be empty afterwards.         |
| Hooks and repository-local config are not captured                                       | design | `.git/hooks`, `.git/config` beyond remotes and upstreams (e.g. `user.email` overrides, sparse-checkout) and `.git/info/exclude` stay behind. Hooks are executable code; migrating them silently would be a security decision the user did not make, and restore runs with `core.hooksPath=/dev/null`. |
| In-progress operations are not captured                                                  | gap    | A rebase, merge, cherry-pick or bisect in progress (`.git/rebase-merge`, `MERGE_HEAD`, …) is not representable as staged/unstaged diffs. Finish or abort the operation first.                                                                                                                         |
| Unmerged (conflicted) index entries and intent-to-add entries                            | gap    | Restored as plain modifications (conflict markers travel); the unmerged index state and `git add -N` markers cannot be reproduced.                                                                                                                                                                    |
| Reflog is not migrated                                                                   | design | Bundles carry refs and objects, not reflogs. Unreachable commits (only in the reflog) are lost.                                                                                                                                                                                                       |
| Git LFS objects                                                                          | gap    | LFS pointer files travel with the bundle; the large objects do not. `git lfs fetch --all` / `git lfs pull` after restore re-fetches them from the remote.                                                                                                                                             |
| Ignored files only when explicitly selected                                              | design | `node_modules`, build output and other ignored content are excluded unless the user opts in per entry (top two directory levels are offered; env files are offered via the project-files provider).                                                                                                   |
| Untracked symlinks, nested repositories and special files are skipped                    | design | Never followed or packed; listed in `state.json` (`excludedUntrackedPaths`) and accounted for by the verifier. Recreate them by hand.                                                                                                                                                                 |
| Untracked credential files are never migrated                                            | design | `id_rsa`, `*.pem`, `.netrc`, … found untracked in a worktree are shown but not selectable (not even opt-in).                                                                                                                                                                                          |
| File ownership, extended attributes and timestamps are not preserved for untracked files | design | Copies preserve mode bits (executable), not xattrs, ACLs or ownership.                                                                                                                                                                                                                                |
| Worktrees whose directory no longer exists                                               | design | Prunable/missing worktrees are listed in `repository.json` but produce no state and are not recreated.                                                                                                                                                                                                |
| A branch checked out in two restored worktrees                                           | design | Git refuses; the second worktree is skipped with a warning.                                                                                                                                                                                                                                           |
| Detached-HEAD worktrees                                                                  | design | Restored detached at the same commit; no branch is invented.                                                                                                                                                                                                                                          |
| Diffs that no longer apply                                                               | design | If `git apply` fails on the destination the repository stays restored, the outcome is `partial` (`GIT_APPLY_FAILED`) and the diff files are left in `<worktree>/.devmig-unapplied/` for manual application.                                                                                           |
| `git status` is compared literally                                                       | design | A destination with different `core.autocrlf`/filter configuration may report a verification mismatch even though the content is identical.                                                                                                                                                            |
| Global git configuration and credentials                                                 | design | `~/.gitconfig`, credential helpers, `~/.ssh` and signing keys are never part of a backup.                                                                                                                                                                                                             |

## Claude Code provider

| Limitation                                                                | Kind   | Notes                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Credentials are never migrated                                            | design | The macOS Keychain item (`Claude Code-credentials`), the `oauthAccount`, `userID` and `machineID` blocks of `~/.claude.json`, `sessions/*.key` and MCP OAuth tokens stay behind. Sign in again on the destination.                                                                                                                    |
| Plugins are reinstalled, not copied                                       | design | `~/.claude/plugins/cache` and `plugins/marketplaces` are machine-specific clones with absolute paths. The backup carries the plugin **manifest** (`installed_plugins.json`, `known_marketplaces.json`, `plugins/data/`); Claude Code re-fetches the plugins, which needs network access.                                              |
| Project directory-name encoding beyond 200 characters is a hypothesis     | gap    | Claude Code truncates encoded names over 200 characters and appends an undocumented hash. The app never guesses the hash: when the path is unchanged the original directory name is reused; otherwise the session set is restored under the truncated name, marked **unverifiable**, and the report says where it is.                 |
| Non-ASCII project paths                                                   | gap    | Whether Claude Code treats "alphanumeric" as ASCII-only is unverified; the provider assumes ASCII (non-ASCII letters become `-`). The per-machine verification (preflight `claude-encoding`) flags a mismatch, and such projects may end up in the warn path above ([ADR-0004](architecture/adr/0004-claude-project-matching.md)).    |
| Conversation text is not rewritten on path change                         | design | Only schema-owned path fields are remapped ([ADR-0005](architecture/adr/0005-path-remapping.md)). Old paths quoted in messages and tool inputs, `CLAUDE.md` `@` imports, hook commands, `statusLine.command`, `permissions.additionalDirectories` and absolute permission rules remain and are listed under _unsupported references_. |
| Restoring while Claude Code is running is warned against, not blocked     | design | Preflight `claude-running` names the live pids and asks you to quit; merges are add-only and writes atomic, and a copy of `~/.claude.json` is kept in `<claudeConfigDir>/devmig-backups/`, but a session started during the restore can still overwrite the entry it rewrites. Quit first.                                            |
| Sessions older than the destination's `cleanupPeriodDays` may be swept    | design | Claude Code's retention sweep (default 30 days) is age-based and restored files carry fresh mtimes only for the files we write; raise `cleanupPeriodDays` before the first launch — this is guidance in the [user guide](USER_GUIDE.md#6-re-authenticate); the app does not warn about it.                                            |
| Workspace trust travels with the project entry                            | design | `hasTrustDialogAccepted` is part of the restored `~/.claude.json` project entry (you restored your own project). Edit the entry if the destination should re-confirm trust; Claude Code may still re-prompt for folders it considers new.                                                                                             |
| `~/.claude.json` is merged entry by entry, never copied whole             | design | Only the selected `projects[...]` entries, user-scope MCP servers (env/headers opt-in) and a fixed list of global config keys are added. `githubRepoPaths`, usage counters, tips state, feature caches and identity blocks are not migrated.                                                                                          |
| `paste-cache/` bodies are not migrated                                    | gap    | `history.jsonl` rows that reference pastes lose the pasted body. `agent-memory/` and user-wide `workflows/` are not migrated either.                                                                                                                                                                                                  |
| Ephemeral state is not migrated                                           | design | `sessions/` (live registry), `shell-snapshots/`, `debug/`, `statsig/`, `cache/`, `ide/`, `telemetry/`, `todos/`, `logs/`, `backups/` and similar are shown for transparency and skipped.                                                                                                                                              |
| `session-env/` is not migrated                                            | design | Per-session environment scripts are written by SessionStart/Setup hooks and may contain secrets the hooks export; Claude Code regenerates them. They are listed as ephemeral.                                                                                                                                                         |
| Transcript format drift                                                   | gap    | The provider validates each JSONL record with a permissive schema and preserves unknown fields, but a future Claude Code version could add path-bearing fields the app does not know; they surface as unsupported references rather than being rewritten.                                                                             |
| Duplicate session ids across two backups                                  | design | Merging is add-only by session id. A session that exists on both machines with different content is kept as `<id>.devmig-conflict.jsonl` and reported; the user decides. Each session lives in exactly one project directory because `claude --resume <id>` refuses duplicates.                                                       |
| Auto memory is per repository root                                        | design | Memory for worktrees is restored under the encoded **repository root** directory, matching Claude Code's own layout; per-worktree memory directories are not created.                                                                                                                                                                 |
| `.claude/settings.local.json` is looked up in the selected directory only | gap    | Not at a differing git root.                                                                                                                                                                                                                                                                                                          |

## Project files and runtime providers

| Limitation                                                    | Kind   | Notes                                                                                                                                                                                                                                                                                     |
| ------------------------------------------------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Env-file detection is name-based plus bounded content sniff   | design | `.env*`, `.envrc`, `.npmrc`/`.yarnrc`, version pins, compose overrides and certificates at the root (and `certs/` two levels deep) are offered; a secret in an unusually named file is not detected. Over-classification is preferred.                                                    |
| Editor state is not captured                                  | gap    | `.vscode/`, `.idea/` and similar are not offered in 1.0 (VS Code / Cursor providers are on the [roadmap](ROADMAP.md) for 1.2).                                                                                                                                                            |
| Only git-ignored local files are captured inside a repository | design | Tracked and untracked-but-not-ignored files belong to the Git provider; if Git is not part of a restore, the project-files provider does not recreate them.                                                                                                                               |
| Files above 16 MiB are listed but not selectable              | design |                                                                                                                                                                                                                                                                                           |
| Runtime facts are informational only                          | design | `machine.json` records tool versions (git, node, pnpm, npm, bun, claude, gh, brew); the restore itself never installs anything (the 1.1 setup step proposes consent-gated actions). Node compatibility is a major-version comparison; `gh auth status` may contact GitHub (10 s timeout). |
| Only the JavaScript ecosystem is described                    | gap    | Package manager, workspace, Node pin, `engines` and a few frameworks; Python, Rust, Go, Homebrew and Docker are roadmap providers.                                                                                                                                                        |

## Restore behaviour

| Limitation                                                                      | Kind   | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A cancelled or failed restore is partial                                        | design | Individual files are atomic and originals are preserved (`skip` / `merge` / `backup-then-replace`), but there is no whole-restore rollback. The report lists exactly which steps completed; re-running with `skip`/`merge` defaults is safe.                                                                                                                                                                                         |
| `backup-then-replace` on a whole repository directory                           | gap    | The original is moved to `<dest>.devmig-backup-<timestamp>`, a sibling of the approved root. The engine approves that aside path only for collisions decided as `backup-then-replace` — validated end to end by `packages/core/src/restore/restore-engine.integration.test.ts › DefaultRestoreEngine (integration, fake providers + fake archive) › adds announced aside paths to the roots only for backup-then-replace decisions`. |
| Case-insensitive filesystem collisions are rejected, not resolved               | design | Two distinct names that collide on APFS (default, case-insensitive) abort that artifact with an explanation.                                                                                                                                                                                                                                                                                                                         |
| Destinations on network volumes or iCloud Drive are unsupported for Claude data | design | Claude Code refuses network-path worktrees; the preflight warns.                                                                                                                                                                                                                                                                                                                                                                     |
| Projects must be restored to a single machine user                              | design | The Claude config dir and `~/.claude.json` of the current user are the only global destinations.                                                                                                                                                                                                                                                                                                                                     |
| Free space is checked with a fixed margin                                       | design | Extraction and every destination need 1.2 × the payload size available; otherwise the plan fails preflight (`engine:space:*`).                                                                                                                                                                                                                                                                                                       |

## Not yet supported tools

Codex CLI, Cursor, VS Code, Ghostty, Homebrew, Node version managers, Docker volumes — see the
[roadmap](ROADMAP.md). New providers are the easiest contribution; start with [AUTHORING.md](providers/AUTHORING.md).

## Validation

Where a limitation is enforced or reported by code, the test that demonstrates it:

- Git stash / submodule / sensitive-untracked reporting — validated by:
  `packages/providers/git/src/git-provider.integration.test.ts › GitProvider round trip (real git) › scans the repository, its worktree, ignored and sensitive entries`
- Diffs that no longer apply stay in `.devmig-unapplied/` — validated by:
  `packages/providers/git/src/git-provider.integration.test.ts › … › keeps the repository and preserves diffs when a patch no longer applies`
- Claude encoding hypothesis and the >200-character warn path — validated by:
  `packages/providers/claude-code/src/encoding.test.ts › encodeProjectDirName › never guesses the hash suffix for names longer than 200 characters`,
  `… › verifyEncoding › reports mismatches and does not verify`
- Extraction limits — validated by:
  `packages/archive/src/archive.test.ts › limits › enforces maxEntries, maxTotalBytes, maxEntryBytes and maxPathLength and cleans up`
- Add-only merge and conflict files — validated by:
  `packages/providers/claude-code/src/merge.test.ts › session merge › skips identical transcripts, keeps differing ones as conflict files, and merges memory add-only`,
  `packages/providers/claude-code/src/provider.integration.test.ts › … › reports collisions on a second restore and skips identical content`
- Credentials never migrated — validated by:
  `packages/providers/claude-code/src/merge.test.ts › ~/.claude.json merge › adds entries under the new path, backs up the original, never writes identity keys or MCP env unless selected`
- `backup-then-replace` aside paths for repositories — validated by:
  `packages/core/src/restore/restore-engine.integration.test.ts › DefaultRestoreEngine (integration, fake providers + fake archive) › adds announced aside paths to the roots only for backup-then-replace decisions`,
  `packages/core/src/restore/aside-paths.test.ts › approveAsideRoots › approves sibling asides and paths inside roots; rejects everything else`

## Desktop app

- The Playwright E2E suite drives the built `out/` tree with the stock Electron binary; the packaged `.app` cannot be
  driven by Playwright because its fuses disable `--inspect`. The packaged app is verified by launching it directly.
- The Backup Review screen counts the primary worktree plus linked worktrees, while the manifest counts linked
  worktrees only.
- Stale staging directories left by a crash are removed on the next start only when older than 24 hours.
- In `electron-vite dev` the renderer relies on the meta CSP in `index.html`; packaged builds get the strict
  production CSP.
- Packaged builds flip `RunAsNode`/`NodeOptions`/`NodeCliInspect` off and `OnlyLoadAppFromAsar`/`EmbeddedAsarIntegrity`
  on; verify with `npx @electron/fuses read --app "…/Dev Migration Assistant.app"`.
- In `electron-vite dev` without a complete preload bridge the renderer falls back to in-memory mock data and shows a
  "Preview data" badge; packaged builds always use the real bridge.
