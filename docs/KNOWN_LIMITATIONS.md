# Known limitations (v0.1)

**Status: to be finalized before the v0.1 release.** This list is derived from the ADRs and research notes; the
integrator confirms each row against the shipped code and fills in the `validated by` test names. Items marked
_design_ are deliberate; items marked _gap_ are things we would like to do and have not done yet. Nothing here
is hidden from the user: where the app cannot capture or restore something, the scan summary, restore plan or
final report says so.

## Platform and distribution

| Limitation                                                          | Kind   | Notes                                                                                                                                            |
| ------------------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| macOS 13+ on Apple Silicon only; no Intel build, no universal build | gap    | Universal build on the [roadmap](ROADMAP.md) for v0.2.                                                                                           |
| No Windows or Linux                                                 | design | Path semantics (`~`, case sensitivity, Claude config location) differ; a read-only restore tool for other platforms is a v1 idea at most.        |
| Unsigned, un-notarized DMG                                          | gap    | Gatekeeper requires right-click → Open. Signing is wired in `release.yml` and only needs certificate secrets ([RELEASE.md](release/RELEASE.md)). |
| No auto-update                                                      | design | Download the next release from GitHub. No network code path exists in the app.                                                                   |
| No command-line interface                                           | gap    | `@devmig/core` is headless and testable, but v0.1 ships no CLI binary.                                                                           |
| English only                                                        | gap    |                                                                                                                                                  |

## The `.devbackup` container

| Limitation                                                           | Kind   | Notes                                                                                                                                                                                                                                                     |
| -------------------------------------------------------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No password recovery                                                 | gap    | A forgotten password means an unreadable backup. A recovery key (second key wrap in the header, `formatVersion` 2) is planned for v0.2.                                                                                                                   |
| No compression                                                       | gap    | Transcripts compress 5–10×; v0.1 stores the tar stream uncompressed inside the encryption so the extraction path has no decompression surface. Optional gzip inside the encryption is planned ([ADR-0003](architecture/adr/0003-devbackup-container.md)). |
| One file, whole payload                                              | design | No incremental or differential backups; every backup is complete. The file can be large (tens of GB for big monorepos); FAT32 media cannot hold files over 4 GiB.                                                                                         |
| Hard size limits on restore                                          | design | Extraction refuses payloads over 200 GiB total, 2,000,000 entries, 50 GiB per entry or 1024-character paths (`DEFAULT_EXTRACTION_LIMITS`). The GCM construction itself has no size ceiling because the payload is chunked.                                |
| Header metadata is visible without the password                      | design | Format version, KDF parameters, creation time, app version and the approximate size are readable by anyone holding the file. No labels, paths or names are in the header.                                                                                 |
| Argon2id default cost needs ~256 MiB RAM and ~0.5 s on Apple Silicon | design | Older or memory-constrained machines take longer to open a backup. Readers accept parameters down to the RFC 9106 floor and cap them at 1 GiB / t 16 / p 16 so a hostile header cannot demand more.                                                       |
| A corrupted backup is unrecoverable                                  | design | Authenticated encryption fails closed on the first bad chunk; there is no error-correction data. Keep two copies of important backups.                                                                                                                    |

## Git provider

| Limitation                                                                               | Kind   | Notes                                                                                                                                                                                                                                                   |
| ---------------------------------------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Submodules are not captured                                                              | gap    | The bundle covers the superproject only; submodule checkouts must be re-initialised (`git submodule update --init`) on the destination, and their local changes are not migrated. The scan warns when `.gitmodules` exists.                             |
| Stashes are not captured                                                                 | gap    | `git bundle --all` includes refs, not `refs/stash`. Apply or drop stashes before backing up; `git stash list` is expected to be empty after restore.                                                                                                    |
| Hooks and repository-local config are not captured                                       | design | `.git/hooks`, `.git/config` beyond remotes (e.g. `user.email` overrides, sparse-checkout, `core.hooksPath`) and `.git/info/exclude` stay behind. Hooks are executable code; migrating them silently would be a security decision the user did not make. |
| In-progress operations are not captured                                                  | gap    | A rebase, merge, cherry-pick or bisect in progress (`.git/rebase-merge`, `MERGE_HEAD`, …) is not representable as staged/unstaged diffs. The scan warns; finish or abort the operation first.                                                           |
| Unmerged (conflicted) index entries and intent-to-add entries                            | gap    | `git diff --cached --binary` cannot express them. The plan warns and restores the rest.                                                                                                                                                                 |
| Reflog is not migrated                                                                   | design | Bundles carry refs and objects, not reflogs. Unreachable commits (only in the reflog) are lost.                                                                                                                                                         |
| Git LFS objects                                                                          | gap    | LFS pointer files travel with the bundle; the large objects do not. `git lfs pull` after restore re-fetches them from the remote.                                                                                                                       |
| Ignored files only when explicitly selected                                              | design | `node_modules`, build output and other ignored content are excluded unless the user opts in per artifact (env files are offered via the project-files provider).                                                                                        |
| Symlinks inside the working tree are skipped                                             | design | Symlinks are never followed or packed; they are listed in the manifest and the restore report. Recreate them by hand.                                                                                                                                   |
| File ownership, extended attributes and timestamps are not preserved for untracked files | design | Copies preserve mode bits (executable), not xattrs, ACLs or ownership.                                                                                                                                                                                  |
| Worktrees located outside the project's parent directory                                 | gap    | Worktrees whose path cannot be expressed relative to the primary worktree are restored under the mapped project path; the plan shows the new location.                                                                                                  |
| Detached-HEAD worktrees                                                                  | design | Restored detached at the same commit; no branch is invented.                                                                                                                                                                                            |
| Global git configuration and credentials                                                 | design | `~/.gitconfig`, credential helpers, `~/.ssh` and signing keys are never part of a backup.                                                                                                                                                               |

## Claude Code provider

| Limitation                                                             | Kind   | Notes                                                                                                                                                                                                                                                                                                             |
| ---------------------------------------------------------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Credentials are never migrated                                         | design | The macOS Keychain item (`Claude Code-credentials`), the `oauthAccount`, `userID` and `machineID` blocks of `~/.claude.json`, and MCP OAuth tokens stay behind. Sign in again on the destination.                                                                                                                 |
| Plugins are reinstalled, not copied                                    | design | `~/.claude/plugins/cache` and `marketplaces` are machine-specific clones with absolute paths. The backup carries the plugin **manifest** (enabled plugins, known marketplaces); the restore report lists what to reinstall. Reinstalling needs network access. `plugins/data/<id>` is opt-in.                     |
| Project directory-name encoding beyond 200 characters is a hypothesis  | gap    | Claude Code truncates encoded names over 200 characters and appends an undocumented hash. The app verifies the observed encoding per machine ([ADR-0004](architecture/adr/0004-claude-project-matching.md)); when it cannot verify, sessions are restored with a **warn** and the report explains where they are. |
| Non-ASCII project paths                                                | gap    | Whether Claude Code treats "alphanumeric" as ASCII-only is unverified; the per-machine verification catches mismatches but such projects may end up in the warn path above.                                                                                                                                       |
| Conversation text is not rewritten on path change                      | design | Only schema-owned path fields are remapped ([ADR-0005](architecture/adr/0005-path-remapping.md)). Old paths quoted in messages, tool inputs, `CLAUDE.md` files, hooks and `statusLine` commands remain and are listed under _unsupported references_.                                                             |
| Sessions older than the destination's `cleanupPeriodDays` may be swept | design | Claude Code's retention sweep (default 30 days) is age-based. The report warns; raise `cleanupPeriodDays` before the first launch ([USER_GUIDE](USER_GUIDE.md#6-re-authenticate)).                                                                                                                                |
| Workspace trust is not carried                                         | design | `hasTrustDialogAccepted` is a security decision; Claude Code asks again on the new machine.                                                                                                                                                                                                                       |
| `~/.claude.json` is merged entry by entry, never copied whole          | design | Only the selected `projects[...]` entries are added. Global config keys, usage counters, tips state and identity blocks are not migrated.                                                                                                                                                                         |
| Ephemeral state is not migrated                                        | design | `sessions/` (live registry), `session-env/`, `shell-snapshots/`, `debug/`, `statsig/`, caches, `.last-*` markers, `security/` venvs and similar are shown for transparency and skipped.                                                                                                                           |
| Transcript format drift                                                | gap    | The provider validates each JSONL record with a permissive schema and preserves unknown fields, but a future Claude Code version could add path-bearing fields the app does not know; they would surface as unsupported references rather than be rewritten.                                                      |
| Duplicate session ids across two backups                               | design | Merging is add-only by session id. A session that exists on both machines with different content is kept as `<id>.devmig-conflict.jsonl` and reported; the user decides.                                                                                                                                          |
| Auto memory is per repository root                                     | design | Memory for worktrees is restored under the encoded **repository root** directory, matching Claude Code's own layout; per-worktree memory directories are not created.                                                                                                                                             |

## Project files and runtime providers

| Limitation                                               | Kind   | Notes                                                                                                                                                                 |
| -------------------------------------------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Env-file detection is name-based plus content heuristics | design | `.env*`, common tool config and files the secret classifier flags are offered; a secret in an unusually named file is not detected. Over-classification is preferred. |
| Runtime facts are informational only                     | design | `machine.json` records tool versions (git, node, claude, …); the app never installs anything. Node version managers, Homebrew and Docker are roadmap providers.       |

## Restore behaviour

| Limitation                                                                      | Kind   | Notes                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A cancelled or failed restore is partial                                        | design | Individual files are atomic and originals are preserved (`skip` / `backup-then-replace`), but there is no whole-restore rollback. The report lists exactly which steps completed; re-running with `skip` defaults is safe. |
| Case-insensitive filesystem collisions are rejected, not resolved               | design | Two distinct names that collide on APFS (default, case-insensitive) abort that artifact with an explanation.                                                                                                               |
| Destinations on network volumes or iCloud Drive are unsupported for Claude data | design | Claude Code refuses network-path worktrees; the preflight warns.                                                                                                                                                           |
| Projects must be restored to a single machine user                              | design | The Claude config dir and `~/.claude.json` of the current user are the only global destinations.                                                                                                                           |

## Not yet supported tools

Codex CLI, Cursor, VS Code, Ghostty, Homebrew, Node version managers, Docker volumes — see the
[roadmap](ROADMAP.md). New providers are the easiest contribution; start with [AUTHORING.md](providers/AUTHORING.md).
